# 0044 — 1.10 feedback batch: boundary-accurate speakers, adaptive summaries, refresh-on-naming, trusted voiceprints

- **Status:** Implemented (pending owner smoke) — DER gate unchanged at 5.7–10.3% vs pinned maxima; full cargo/pnpm suites green
- **Owner agent(s):** audio-engineer (WS1), llm-pipeline-engineer (WS2), rust-core-engineer (WS3/WS4)
- **Roadmap phase:** Identity & Organization (follows 0041/0043)

## Context / Problem

Owner dogfooding v1.10.x (2026-08-02) surfaced four issues:

1. **Speaker names "off by one segment."** At nearly every speaker change, the new
   speaker's first sentence is attributed to the previous speaker. Root cause (verified
   against `silero-rs` rev `26a6460` source): a transcript row is one VAD segment, and a
   `SpeechEnd` only fires after **redemption** silence (400 ms live —
   `audio/stt_stage.rs:19`; 2000 ms batch — `audio/import.rs:54`,
   `audio/retranscription.rs:48`). Real conversational handoff gaps are ~200–300 ms, so a
   quick reply **merges the previous speaker's tail and the new speaker's onset into one
   row**, which then takes a single max-overlap label (`diarization/align.rs:157`) —
   usually the previous speaker's. Compounding it, every stored row is padded outward:
   `start` is 300 ms early (`PRE_SPEECH_PAD_MS`, `audio/vad.rs:42`) and `end` is 400 ms
   late (`POST_SPEECH_PAD_MS`, applied inside silero's `SpeechEnd` on both live and batch
   paths), biasing boundary overlaps toward the earlier speaker.
2. **Summaries are one-size-fits-all.** The prompts contain no length guidance at all
   (`summary/processor.rs:357` fills a fixed template); meeting length only changes
   chunking strategy, never the asked-for depth. Short standups and 90-minute reviews get
   the same-sized report.
3. **Summary lands before speakers do.** specs/0041 WS2 already regenerates a
   speakerless summary after the diarization pass — but nothing re-runs it when names
   actually become real: confirming a suggestion chip, renaming, attendee/person
   assignment, or merging speakers never re-summarizes
   (`api_assign_speaker_to_person` etc. → no refresh hook). The backlog already points at
   the generalization: a `summary_inputs_changed`-style invalidation (BACKLOG.md:38).
3. (cont.) The 0041 decision matrix also refuses to refresh once `speaker_attributed=1`,
   so a summary refreshed with "Speaker 1/Speaker 2" placeholder names is considered done
   and never picks up the real names.
4. **Everyone must be confirmed by hand.** Auto-labeling requires a gallery match at
   cosine ≥ 0.7 **plus** a corroborating calendar-attendee email
   (`diarization/identity.rs:281`). A well-trained voiceprint can never auto-assign on
   voice alone, so the owner re-confirms the same colleagues meeting after meeting.

## Goals

- A speaker change lands on the right sentence: rows that straddle a diarization turn
  boundary are split and each part labeled correctly. Measured: no DER regression on the
  ground-truth harness; unit fixtures prove the split.
- Summary depth tracks meeting size/content (short meeting → short summary), via prompt
  guidance derived from transcript size.
- Naming a speaker (any path: chip, rename, attendee, person, merge) refreshes a
  pristine summary with the real names, debounced so a burst of assignments causes one
  regeneration.
- A person with a well-trained voiceprint gallery is auto-assigned on voice alone past a
  high confidence bar; thin galleries stay confirm-first.

## Non-goals

- Re-transcribing split sub-spans through STT (text is apportioned by time, not
  re-decoded). Plumbing Parakeet word timestamps (`parakeet_engine/model.rs:26` has them;
  discarded at `parakeet_engine/parakeet_engine.rs:501`) is the follow-up that makes
  splits word-exact — out of scope here.
- Changing VAD redemption windows (would trade STT quality for granularity; the split
  fixes the attribution without touching STT chunking).
- Auto-assigning "You"/the owner (mic-channel short-circuit is untouched).
- Summary length user setting (prompt-derived only, revisit if guidance is insufficient).

## Design

### WS1 — boundary-accurate speaker attribution (audio-engineer)

**W1.1 Pad-compensated alignment.** New pure helper in `diarization/align.rs`:
`pad_trimmed(start, end) -> (f32, f32)` shrinking a segment by up to
`PRE_SPEECH_PAD_MS`/`POST_SPEECH_PAD_MS` while keeping ≥ 250 ms of core (trim
proportionally when the row is shorter). Used by offline `load_segments`
(`diarization/pipeline.rs:269`) and the live path's window build
(`diarization/live.rs:497`) before overlap scoring. Stored row timestamps are NOT
changed (playback anchoring keeps the pads).

**W1.2 Split rows that straddle a speaker change.** New module `diarization/split.rs`,
pure planning + a persistence step in the offline pass (between `load_segments` and
alignment in `pipeline.rs::run`):

- *Eligibility:* row is not `Channel::Microphone`; row has **no** row in
  `transcript_speaker_overrides` (override ids must stay stable — specs/0019); row text
  splits on whitespace into ≥ 2 words.
- *Plan:* on the pad-trimmed core, compute per-turn overlaps. Split points are the
  boundaries between consecutive overlapping turns of **different** speakers where each
  side's overlap ≥ `MIN_SPLIT_PART_SECS = 0.75`. Cap at 4 parts. Boundary time = midpoint
  of the two turns' adjacent edges, clamped inside the row.
- *Text apportioning:* character offset proportional to each part's share of the core
  duration, snapped to the nearest whitespace; a part that would get an empty/whitespace
  text cancels that split point.
- *Persist:* first part UPDATEs the original row (same `transcripts.id` — overrides and
  FTS stay coherent via the existing `AFTER UPDATE OF transcript` trigger); later parts
  INSERT new rows (new uuid, same meeting/channel/confidence, `timestamp` interpolated).
  All inside one transaction, before alignment, so alignment + persist label the parts.
- *Idempotent:* re-runs see already-tight parts (single-turn overlap) and plan no splits.

**Verification:** unit tests for plan + apportioning; integration test over a synthetic
two-speaker fixture (fast handoff merged row → split + correct labels);
`diarization_tuning.rs` ground-truth run must not regress `EVAL_PINNED_DER`.

### WS2 — adaptive summary length (llm-pipeline-engineer)

Pure fn in `summary/processor.rs`: `length_guidance(transcript_words: usize) -> String`
mapping size bands to an explicit depth instruction (≈ <1.5k words → "brief: a few
sentences per section, omit empty sections"; 1.5k–8k → standard; >8k → "detailed,
comprehensive"), always including: *"Scale the report to the meeting's actual content —
do not pad a short meeting or compress a long, dense one."* Injected into
`build_final_report_system_prompt` and `build_final_synthesis_system_prompt`
(single-pass and map-reduce paths). Unit tests over the band edges.

### WS3 — summary refresh on speaker naming (rust-core-engineer)

- **Fingerprint what the summary saw.** Migration adds
  `summary_processes.speaker_names_hash TEXT NULL` — a stable hash of the resolved
  per-speaker display names at generation time (computed in
  `service.rs::process_transcript_background` beside `speaker_attributed`).
- **Generalized decision.** `summary/refresh.rs` gains
  `decide_name_refresh(current_names_hash, snapshot)`: refresh iff summary COMPLETED,
  pristine (existing `generated_markdown_hash` guard), and `speaker_names_hash` differs
  from the current resolved set. (The 0041 `speaker_attributed` matrix stays for the
  post-diarization trigger; placeholder→real-name changes now pass via the hash.)
- **Debounced trigger.** `refresh.rs::schedule_name_refresh(app, meeting_id)`: per-meeting
  reset-on-call 20 s timer (tokio task + registry map), then run the same
  wait-behind-in-flight refresh path. Called after successful mutation in
  `api_rename_speaker`, `api_assign_speaker_to_person`, `api_assign_speaker_to_attendee`,
  `api_merge_speakers` (and the suggestion-chip accept path, which routes through these).
- UI: unchanged — existing `summary-refresh-started` event and "Updating with speaker
  names…" badge cover it.

### WS4 — trusted-voiceprint auto-assign (rust-core-engineer)

- `identity.rs`: candidates gain `gallery_sample_count: usize`. New consts
  `TAU_VOICE_AUTO = 0.80`, `TRUSTED_GALLERY_MIN_SAMPLES = 3`. Auto-label rule becomes:
  *(existing)* gallery ∧ ≥ `TAU_AUTO_LABEL` ∧ email-corroborated, **or** *(new)* gallery ∧
  ≥ `TAU_VOICE_AUTO` ∧ margin ∧ `gallery_sample_count ≥ TRUSTED_GALLERY_MIN_SAMPLES`.
  Owner remains excluded (0043 W1.4).
- `pipeline.rs::compute_suggestions_with_emails`: thread each person's enrollment count
  from the voiceprints repository into the candidate set.
- Enroll-on-confirm (`people/enroll.rs`) is unchanged and is what grows a gallery to
  "trusted" naturally.

## Acceptance criteria

- Synthetic fast-handoff fixture: merged row is split at the turn boundary and both
  parts carry the correct speaker; a row with a manual override is never split.
- `EVAL_PINNED_DER` does not regress on the three ground-truth samples.
- Summary prompts for a ~500-word and a ~20k-word transcript contain different explicit
  depth instructions (unit-assertable).
- Renaming/assigning a speaker on a meeting with a pristine completed summary triggers
  exactly one regeneration after the debounce window; an edited summary is untouched.
- A gallery person with ≥ 3 enrollments auto-labels at cosine ≥ 0.80 without email
  corroboration; with 2 enrollments or cosine 0.79 they remain a suggestion.
- Definition of Done per `/CLAUDE.md` (cargo check/clippy/test, pnpm lint/test,
  file-size ratchet). Ratchet note: the batch also decomposed four allowlisted
  monoliths (new `summary/length.rs`, `diarization/segments.rs`,
  `diarization/corrections.rs`; attribution loader into `summary/refresh.rs`) and
  tightened their allowlist entries.

## Risks / open questions

- **Time-proportional text splits are approximate.** Whitespace snapping keeps words
  intact but a split can land a few words off. Accepted: today the *entire sentence* is
  on the wrong speaker; the recovery path (0039 WS2 span correction) still works. Word
  timestamps (Parakeet re-plumb) is the precision follow-up.
- **Splitting mutates transcript rows** other features read (FTS: covered by triggers;
  overrides: excluded rows; `transcript_chunks`/action items: verify no id coupling
  during implementation).
- Debounce window (20 s) is a guess; tune if the owner notices double runs or lag.
- Cloud-provider cost of extra regenerations — bounded by pristine guard + hash
  comparison (no-op unless names actually changed).
